# Per-channel documentation reorg — design

**Date:** 2026-06-24
**Status:** Approved for spec review
**Repo:** `documentation` (Docusaurus 3.7, classic preset, deploys to docs.bookhead.net)

## Goal

Reorganize the Bookhead documentation site from a single shared docs tree into
**independent, self-contained sections** — one per sales channel, plus a Core
platform section and a standalone Canva section.

The immediate business driver: a **Shopify-only** section that a Shopify App
Store reviewer and Shopify merchants land in directly from the app listing. That
section must tell **only the Shopify story** — no other sales channel named
anywhere a Shopify visitor can see it (sidebar, navbar, or footer).

## Hard constraints

1. The Shopify section mentions **no other sales channel anywhere** visible from
   its pages.
2. The terms **"point of sale"** and **"POS"** are never used, in any section.
3. Existing live pages must keep working (`onBrokenLinks: 'throw'` — the build
   fails on any broken internal link, so every moved page needs its links fixed).

## Architecture — independent Docusaurus doc instances

One site, several walled-off doc instances. The Core section is the existing
preset `docs` instance; each other section is a separate
`@docusaurus/plugin-content-docs` instance registered in `docusaurus.config.js`,
each with its own `id`, `path`, `routeBasePath`, and autogenerated sidebar.

| Section | URL base | Content folder | Plugin id | Sidebar shows |
|---|---|---|---|---|
| Core / Platform | `/docs` | `docs/` | (default) | Platform pages only |
| Shopify | `/shopify` | `shopify/` | `shopify` | Shopify only |
| Squarespace | `/squarespace` | `squarespace/` | `squarespace` | Squarespace only |
| eBay | `/ebay` | `ebay/` | `ebay` | eBay only |
| Biblio | `/biblio` | `biblio/` | `biblio` | Biblio only |
| Alibris | `/alibris` | `alibris/` | `alibris` | Alibris only |
| Canva | `/canva` | `canva/` | `canva` | Canva family only |
| Google Sheets | `/sheets` | `sheets/` | `sheets` | Sheets only |

Each instance's sidebar is autogenerated (`{type: 'autogenerated', dirName: '.'}`)
from its own folder, so no section can ever display another section's pages.
Page order within a section is controlled by `sidebar_position` frontmatter.

### Channel-neutral global chrome (the isolation decision)

Docusaurus's navbar and footer are **global** (shared by every page), so they are
the only place other channels could leak into a Shopify visitor's view. They are
made channel-neutral:

- **Navbar:** `Documentation` (→ Core `/docs`) + `Bookhead site`. No channel
  dropdown, no per-channel entries. Channel sections are reached by direct URL
  (e.g. the App Store link to `/shopify`) and from links inside Core.
- **Footer:** platform/support links only — no channel names.
- **Site tagline** in `docusaurus.config.js` currently reads "Sync your bookstore
  inventory to Squarespace, Shopify, eBay, and more." Rewrite to a channel-neutral
  line (e.g. "Documentation for syncing your bookstore inventory online") so no
  channel is named in global metadata.

Trade-off accepted: no top-bar channel switcher. Channel discovery lives inside
Core instead.

## Content mapping

**Rewritten channel-neutral (Core):**
- `intro.md` (Overview) — currently leads with the full channel list. Rewrite to
  describe the platform and bookstore-system integrations generically, then link
  out to channel sections.
- `integrations.md` — keep bookstore systems (Booklog, IBID, Basil); move
  channel-specific rows into their channel sections; replace with neutral pointers.

**Split out of `channels.md`:**
- Squarespace section → seeds `/squarespace`.
- Shopify section → **superseded** by the new richer `/shopify` (do not copy the
  old thinner Shopify copy).
- eBay / Biblio stubs (`[eBay]`, `[Biblio]`) → seed those sections (minimal).
- A neutral **"Sales channels" index page stays in Core** listing + linking to
  each channel section. (This is Core, not a channel section — isolation holds.)

**Stays in Core:** `inventory.md`, `collections.md`, `ftp-integration.md`. Core
has no "Apps & tools" group — every tool is now its own standalone section.

**Moves to standalone `/canva` (the whole Canva family):** `canva-app.md`
(Bookhead for Canva), `design-rss.md` (DesignRSS for Canva), and `rss-worker.md`
(RSS Worker API — exists to back the DesignRSS Canva app).

**Moves to standalone `/sheets`:** `isbn-magic.md` (ISBN Magic for Google
Sheets), keeping its example-sheet links intact.

**New content (no source today):** `eBay`, `Biblio`, `Alibris`. Per user, these
are **minimal "email us" contact stubs** — one short page each: what the
integration is in a sentence and a `support@bookhead.net` contact. No workflows,
no invented detail.

## The Shopify section (`/shopify`) — full content

Six pages, in this order, Shopify-only language throughout. No other channel, no
"point of sale"/"POS".

### 1. Overview — Bookhead for Shopify (`sidebar_position: 1`)
Leads with the one-directional flow, shown prominently near the top:

> **External source → Bookhead (enrich: covers + bibliographic data) → your Shopify store**

- Inventory enters from a **distributor file** or **manual entry**.
- Bookhead **enriches** it (covers + bibliographic data).
- Bookhead **writes** it to the merchant's **own Shopify store**.
- The app **reads** the store's existing Shopify catalog **only to keep inventory
  in sync** — Shopify is not a source of new inventory.
- Make the direction explicit and visual (a simple arrow diagram in Markdown).

### 2. Installing the app (`sidebar_position: 2`)
How a merchant installs Bookhead from the Shopify App Store, authorizes it
against their own Shopify store, and what to expect on first connect.

### 3. Choosing your inventory source (`sidebar_position: 3`)
Three sources, in priority order:
1. **Distributor file (recommended / primary)** → links to page 4.
2. **Manual book creation** → links to page 5.
3. **An external in-store sales system** (renamed from "external POS" to honor the
   no-"POS" rule).

States plainly: **Shopify is not treated as the source of new inventory; the app
reads it only to stay in sync.**

### 4. Importing a distributor file (`sidebar_position: 4`) — most complete page
The Ingram **"receiving a shipment"** workflow, step by step, end to end:
exporting/obtaining the distributor file, getting it into Bookhead, what Bookhead
does (dedupe against the Shopify catalog, enrich, create/update), and how to
confirm the results in the merchant's Shopify store. This is the deepest page.

### 5. Creating book products manually (`sidebar_position: 5`)
Creating a single book product by hand (ISBN, quantity, price → enriched product),
and when to use this vs. a distributor file.

### 6. How syncing works (`sidebar_position: 6`)
- Bookhead **reads** Shopify for **sync and dedupe**.
- Bookhead **writes** new/updated products to the merchant's **own Shopify store
  only**.
- Reiterate the one-directional model; clarify what "in sync" means and cadence.

## Implementation order (phased so the App Store listing is unblocked first)

1. **Scaffold:** add the instance plugins in `docusaurus.config.js`; create a
   sidebar file per instance; make navbar/footer/tagline channel-neutral.
2. **Shopify:** build all six pages fully. (Unblocks the App Store listing.)
3. **Core rewrite:** neutral Overview + Integrations; add Core "Sales channels"
   index and "Apps & tools" group.
4. **Canva + Sheets:** move `canva-app` + `design-rss` + `rss-worker` into
   `/canva`; move `isbn-magic` into `/sheets`.
5. **Squarespace:** migrate from `channels.md` / `integrations.md`.
6. **eBay / Biblio / Alibris:** seed minimal "email us" stubs.
7. **Fix links + verify:** update all internal links; run `yarn build` — broken
   links throw, giving a hard pass/fail.
